# AUTO DNS query selection implementation

Implement the design agreed in chat: full startup discovery for each domain/resolver
and each configured query type; reliability first, estimated bytes/RTT second;
periodic checks at the negotiated MTU; failure checks and bounded recovery;
restart at a smaller MTU only when no compatible path remains and config permits.

All thresholds use the 14 DNS_AUTO_* settings. Existing MTU discovery bounds,
retry counts and startup concurrency continue to apply. Default mode remains TXT.

Implementation tasks:
1. Enable AUTO configuration, introduce per-path transport selection, explicit
   query types for probes/session requests, and atomic balancer publication.
2. Discover and rank candidate transports, validate nonce and size, publish initial
   profiles; AUTO startup always bypasses cached MTU values.
3. Schedule bounded periodic/failure probes, confirm switches, ignore obsolete
   request generations, and coordinate emergency recovery through the main loop.
4. Add local UDP integration and lifecycle tests, update user documentation, run
   full tests, vet, builds, and supported race checks; perform a final self-review
   (no subagent tool is available).

Progress: all four tasks are complete. AUTO accepts and uses all 14 policy
settings. There are 23 AUTO behavior/integration tests, including a real local
server, SOCKS upstream and an already-connected TCP stream that survives an
automatic SRV-to-TXT switch after the resolver path changes its filtering.

Verification: go test ./... -count=1, go vet ./..., go build ./..., and git diff
--check passed. The race build was attempted with the installed Zig toolchain,
but could not link the Windows race runtime (WaitOnAddress/WakeByAddress symbols);
no race-instrumented tests ran.

Final review: self-review (no subagent tool). Added failing regression tests and
fixes for overdue-path starvation, old timeouts overriding a newer success, DNS
error answers containing valid tunnel data, and overlooking a compatible type
when a more reliable smaller-MTU candidate ranks ahead of it. Cancellation and
generation checks prevent obsolete results from publishing after runtime stop.

Reconnect rechecks are explicitly independent of the stopped runtime health loop,
and preserve the current MTU when emergency smaller-MTU restarts are disabled.
